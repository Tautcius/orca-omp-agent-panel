# AGENTS.md

omp extension + panel-only Orca plugin that shows the focused worktree's omp
todo list and subagent status in Orca's right sidebar, on stock Orca and stock omp.
Read in this order before touching anything:

1. **`README.md`**: data flow diagram, why the panel is re-rendered as a file,
   install steps, test overview.
2. **`omp-extension/README.md`**: state-file contract (schema v1, location,
   atomic writes, debounce/throttle timings) and known limitations.
3. `omp-extension/orca-omp-agent-panel.ts` header comment, then
   `test/harness.ts` (fake omp `ExtensionAPI` + fake Orca parent).

## Load-bearing rules not obvious from reading files alone

- **Edit `orca-plugin/panel.template.html`, never `orca-plugin/panel.html`.**
  `panel.html` is generated by the extension at runtime and gitignored; any
  hand edit is overwritten on the next render.
- **The data placeholder `/*__OMP_AGENT_DATA__*/null` is a three-way
  contract**: the template (`var DATA = ...`), `DATA_PLACEHOLDER` in the
  extension, and `DATA_PLACEHOLDER` in `test/harness.ts`. Change all three or none.
- **Every write to `panel.html` reloads the panel iframe** (blank flash,
  ~1–2.5 s). Keep the "unchanged bytes must not touch the file" check, the
  1 s render throttle, the 5 s batching of progress-only writes, and keep
  `updatedAt` out of the panel data.
- **The plugin only works as an Orca development plugin.** Installed plugins
  are hash-verified, so a rewritten `panel.html` would not load. Live updates
  rely on undocumented dev-mode reload-on-file-change behaviour.
- **Keep the plugin panel-only (no `main`/worker) with only the
  `workspace:read` capability.** The worker was removed in `a3dd3a3` so it
  runs on stock Orca; sandboxed panels have no network (`connect-src 'none'`)
  and can only call `workspace.readContext`, `terminal.sendText`,
  `notifications.show`. Panel `icon` must be one Orca supports (`662f7b1`
  switched `list-checks` to `bot`).
- **The extension stays dependency-free**: no `@oh-my-pi` type imports, only
  `node:*`. It is loaded via symlink from `~/.omp/agent/extensions`, where no
  `node_modules` resolution exists. It finds `orca-plugin/` through
  `realpath` of its own file, so a copy (not symlink) breaks the default path.
- **The extension symlink must not use an `orca-*` name** (use
  `omp-agent-panel.ts`); Orca manages `orca-*` files in
  `~/.omp/agent/extensions`.
- **State files are schema v1**; the renderer skips any file whose
  `version !== 1`. Bump deliberately and handle old files.
- Tests: `bun install && bun test` (~15 s). They use **real timers**
  (debounce/throttle/poll paths run for real), so don't swap in fake timers
  or shrink `WRITE_SETTLE_MS` below the 150 ms debounce margin.
- **Tests must never touch `orca-plugin/` or the real state dir**
  (`~/.local/state/orca-omp-agent-panel/sessions`). Use `useTempDirs()` from
  `test/harness.ts`, which sets `ORCA_OMP_PANEL_STATE_DIR` and
  `ORCA_OMP_PANEL_PLUGIN_DIR` to a temp copy; a test that skips it writes
  into the live panel of a running Orca.
- Type-check scope is `omp-extension/` and `test/` (`tsconfig.json`, `noEmit`);
  there is no build step.

## Orca workspace status
When running inside an Orca worktree, update the workspace card at checkpoints (repro, fix, verification, blocker, handoff):
`orca worktree set --worktree active --comment "<short current state>" --json`
Set `--workspace-status in-review` when work is ready for review, `completed` after merge. A failed update is not an error.
